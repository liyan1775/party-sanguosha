## 要交付的体验

一个不懂开发的朋友，仅靠随包说明，在另一台 Windows x64 电脑上解压、双击启动，邀请手机玩家扫码，完成一局、返回房间再开一局，最后双击停止。这是首发的主要完成条件。继续提供四模式、两档基础及八档官方将池、原生 AI 和 LAN／临时公网双入口；准备期间先不扩模式、将池或扩展。

允许带着明确的局限发布测试版。不能把模拟验证写成真机通过，也不能把已知导致整台后台退出、越权或暗牌泄漏的问题留给用户碰运气。

## 架构审查结论

现有电脑服务、大厅会话、原生规则执行和手机适配已经分层，无须为了首发整体重写。规则使用固定无名杀，房主权限仍属于参赛玩家，电脑规则宿主不占席位；配置将池也是独立的可审查数据。当前最缺的是从修改到发行的证据与维护约定。

| 边界                 | 审查发现与处理                                                                                                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 上游规则与本项目适配 | 最近借刀、宗护、蒲元等故障涉及选择依赖、恢复状态或牌面过滤。不能推断为上游技能本身未经测试，也不能声称全部技能已无故障。先复现原生执行与手机重建之间的差异，再修共用边界；确有例外时说明理由并补同类回归。   |
| 网络失败与进程寿命   | 复现异常升级 URL、连通性检测超限帧、玩家通道超限帧的未捕获异常。v0.7.11 共用升级 URL 校验，接住 WebSocket 协议错误，让错误连接按协议关闭，保持后台及规则连接可用。新增三项真实套接字回归；不是完整对局证明。 |
| 私有信息与选择恢复   | 保留按接收玩家过滤、入站卡牌 ID 保护、同席位恢复和原截止时间。既有定向测试有证据，但原生动态函数、私人 storage 和新技能执行仍需逐项检查；不将静态扫描当作完整防作弊审计。                                    |
| 源码与交付包         | 纯源码检查、完整资源 API、真实原生对局、Windows 解压启停分别验证。固定 Node／引擎／联网组件并记录哈希；每次发行重建包，不能从用过的目录压缩运行凭据。                                                        |

## 后续改动与发布步骤

1. 定义问题、影响范围和可重复步骤；区分上游规则、适配、数据、网络与设备问题。
2. 完成修复和适当回归，更新对应设计及交接；检查不满足时先修复或明确缩小支持范围。
3. 在自己的 Git 检出运行 `npm run release:check`。不要从嵌在其他仓库中的解压副本扫描父仓库历史。
4. 重新构建 Windows 包，检查 ZIP 内容及 SHA-256，解压后验证启动、对局、重复启动和停止；源码与包内版本应一致。
5. 受邀者按清单试用，记录失败与真实设备结果。公开前落实资源分发依据、私密反馈渠道及发布说明，再由项目主人决定上传。

新版本不追求“所有问题都永远消失”；要能知道支持什么、复现问题、判断改动影响，并交付与说明一致的包。首次测试之后，再根据真实阻碍选择下一项工作，而非继续按功能数量扩张。

## v0.7.13 公开启动包

用户2026-10-15要求提供普通观众可用的发行入口，并允许有需要且具备分发条件时公开完整图片／音频包，取代此前暂缓上传的偏好。当前可执行路径为 Windows x64 启动包：内置运行环境、预构建应用与本机准备工具，首次双击从固定上游下载核心与资源，完成后本机保存。不内置上游游戏素材及衍生小图；不要求玩家安装 Node、Git 或执行 npm。首次准备需电脑能访问 GitHub 和 raw.githubusercontent.com，资源约431 MiB；之后 LAN 游玩不依赖公网。

发布前检查实际 ZIP 的无素材边界、依赖许可、全新临时目录首启、下载中断与继续、真实扫码房间／选将／发牌，以及本目录停止。源码运行、首次联网准备和已缓存后的 LAN 运行分别记录。实际发布状态与证据统一记入 handoff.md，不将候选包当作已经公开。
