# 固定无名杀牌堆核对

核对日期：2026-10-07；实施更新：2026-10-08，项目源码 v0.6.9。用户已确认四模式统一按档位区分牌堆。

结论：四模式统一使用标准27将＋标准108张、进阶48将＋军争160张（去木牛流马）。单挑仍每人一将、一局定胜负；斗地主和2v2保持现有变体，不套用新1v1、智斗三国或4v4专用堆。固定武将、技能及其他模式规则保留。

## 范围与术语

只核对本项目固定的无名杀 v1.11.6、commit `2367607e246d21aae168dba15c01151ee0651f30`。牌包目录来自同版本 [game/package.js](https://github.com/libnoname/noname/blob/2367607e246d21aae168dba15c01151ee0651f30/apps/core/game/package.js)，数据来自已准备的固定核心。没有升级引擎或下载新扩展。

牌包同时提供卡牌规则与可加入牌堆的列表；加载规则不代表把该包的实体牌洗入牌堆。某些包是增补，某些包提供完整模板，还有只用于特定模式或技能的牌。不能把所有包一起勾选便称为“完整三国杀”。

结构化清单在 [config/native-card-inventory.json](../config/native-card-inventory.json)，含每种牌及属性的张数、模式限定定义和来源链接；标记为研究资料，不被正式运行读取。执行 `npm run engine:update-card-inventory` 可从固定核心重新生成，生成器检查 build-info 的 commit，仅解析 AST，不执行卡牌或技能。活动包35条记录的花色/点数是原生导入时随机生成的表达式，清单只统计牌名和数量，不伪造花色/点数。

## 我们现在实际用什么

`config/roster-presets.json` 的cardPile明确指定启用包、排除项与总数；每局start冻结。`runtime/bootstrap.js`按本局配置选择config.cards，`runtime/mode.js`同步lib.configOL.cardPack，并在创建实体牌/inpile之前由card-pile.js排除木牛、校验张数和定义。本项目替换原生start，不执行上述其他变体的牌堆替换。旧运行服务没有cardPilePolicy能力时继续标准108，房间提示更新/重启要求。

| 产品模式   | 使用变体           | 标准27将 | 经典进阶96将 |
| ---------- | ------------------ | -------: | -----------: |
| 身份5–8席  | identity / normal  |  标准108 |      军争160 |
| 斗地主3席  | doudizhu / normal  |  标准108 |      军争160 |
| 2v2四席    | versus / 2v2       |  标准108 |      军争160 |
| 单武将单挑 | single / dianjiang |  标准108 |      军争160 |

标准档加载standard卡牌定义；进阶加载standard、extra、zhulu定义，实体牌只加入standard与extra，去掉1张木牛流马；逐鹿32张不加入。飞扬的`online`版本只选择技能实现，不会把斗地主变体切成online，也不会启用智斗三国107张堆。

“没有实体军争牌”不等于“不会出现军争效果”。界徐晃的断粮可以将黑色非锦囊牌当兵粮寸断；界赵云的原生龙胆还允许桃与酒互换，所需定义已加载。这些虚拟牌按原技能执行，不能用物理牌堆统计否认它们。界刘备的仁德则通过`get.inpileVCardList`提供当前牌堆的基本牌/属性，标准108张会减少酒和属性杀的选项，确实改变进阶武将的可用战术。依据为固定核心refresh的`olduanliang`、`ollongdan`、`rerende`，不改写这些技能。

## 标准与军争的具体差别

| 牌种                       |   标准108 | 标准＋军争161 | 去木牛流马160 |
| -------------------------- | --------: | ------------: | ------------: |
| 普通杀                     |        30 |            30 |            30 |
| 火杀 / 雷杀                |     0 / 0 |         5 / 9 |         5 / 9 |
| 闪                         |        15 |            24 |            24 |
| 桃                         |         8 |            12 |            12 |
| 酒                         |         0 |             5 |             5 |
| 无懈可击                   |         4 |             7 |             7 |
| 火攻 / 铁索连环 / 兵粮寸断 | 0 / 0 / 0 |     3 / 6 / 2 |     3 / 6 / 2 |
| 木牛流马                   |         0 |             1 |             0 |

军争另外加入古锭刀1、朱雀羽扇1、藤甲2、白银狮子1、骅骝1；其他标准实体牌保留。因此本版本的标准＋军争是161张；160张是明确去掉木牛流马的组合，不能把上游53张误写成52张。

## 模式适配判断与已确认方案

| 产品模式 | 对当前选择的判断                                                                            | 建议方向                                                                |
| -------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |

| 2v2      | 已实现OL常规座次/发牌/选将不代表牌堆也已对齐。108适合教学，但没有酒杀、属性伤害和铁索配合。 | 标准档108供入门，进阶档160保留经典配合。                                |
| 单挑     | 本产品是点将单武将单局，用通用108合理；新1v1的52张不是必须。                                | 标准108、进阶160，维持原有单局规则；暂不另造裁剪牌堆。                  |

用户已选择27将108、48将160的统一档位映射，不开放应变、用间、国战或活动牌。这是玩法完整性与熟悉度判断，没有四模式真人胜率的实测依据。

去木牛流马是本项目明确采用的组合，不是声称无名杀2v2默认固定160张或所有OL玩法都相同。固定引擎默认通用配置为standard＋extra，合计161；木牛流马额外涉及扣置牌、装备转移和私人材料恢复，未纳入本轮产品授权。新增军争的火攻公开展示、铁索重铸/连环伤害、酒、兵粮判定、装备与刷新另做真实原生定向验证。

洗入牌堆的配置与definitionPacks分开、在开局冻结、由电脑规则宿主执行；手机与大厅只展示静态规则名称，不暴露当前牌堆顺序。两档四模式已核对实际构造张数与牌种、真实选将/发牌/结算、恢复和隐私；微信真机仍需复测。研究清单生成本身不是可玩证明。
