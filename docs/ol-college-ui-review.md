# 高校联赛练习 UI：官方参考与独立审查

审查日期：2026-10-18。范围为 v0.8.0 本地候选的高校模式及共用斗地主赛前界面。用户确认玩法规则可以保留，本次重点是“叫分／选将像表单、切换和滚动繁琐”以及“牌桌信息拥挤，队友手牌、比分和待命不好用”。本文保留改版前的独立审查依据；用户随后已批准并授权实施，当前实现与验证统一见[开发交接](handoff.md)，不以本报告原先的问题截图代表现状。

结论：当前主要问题来自页面分工和操作状态，没有形成一条连续的比赛流程。计时已经开始，页面却仍在展示大厅宣传；两席候选依次向下堆叠，确认随技能展开移动；进入牌桌后，又把新增信息放到原生界面上方或浮在对手旁边。应先修复这些结构，再调整美术。保留现有无名杀牌桌、规则、动画和信息权限。

## 官方图像中可证实的组织方式

叫分图为 1080×387。左边蓝队放 1、3 号位，右边橙队放 2、4 号位；每席由头像、席号和紧邻的四个候选头像组成。叫分结果贴着对应席位，轮到的右下席有边框高亮和短进度条。红箭头属于说明标注。画面把“是谁、有什么候选、叫到哪里、轮到谁”放在同一紧凑区域，没有上下堆放长段设置。

选将图为 1080×356。两名农民各保留四候选，分别放在上方两区；地主单独置于下方中央，六候选构成一组，其中队友随机补入的两名有说明标注。角色改变通过分区和标题表达，而不是让玩家从长列表自行判断谁还要操作。

两图适合借鉴的原则是：**固定队区与席位、就近呈现当前阶段、候选集中比较、角色确定后只保留相关决策**。图中同时画出各席候选是赛事说明的表达，不能推出本项目应向玩家展示对手候选，或应把待命真人的私人候选继续开放。

图像没有包含完整叫分按钮、换将操作、最终确认、技能详情、农民互看手牌或局间结算。以下对应设计不能冒充官方事实。

## 当前实现的具体问题

当前补拍目录为 [`.runtime/ol-college-ui-review/current/`](../.runtime/ol-college-ui-review/current/)，测量在 [observations.json](../.runtime/ol-college-ui-review/current/observations.json)。DOM 数字描述本次固定候选和视口，不保证所有武将、字体、设备完全相同。

### P0：计时决策被大厅挤到首屏之外

- [03-bidding-landscape.png](../.runtime/ol-college-ui-review/current/03-bidding-landscape.png) 与 [06-choosing-landscape.png](../.runtime/ol-college-ui-review/current/06-choosing-landscape.png)：844×390 下，首屏几乎全部是品牌头部和“好戏，等你入席”大横幅；赛前面板从 y=380 才开始。正在叫分／选将的阶段与动作没有成为当前页面的主体。
- [04-choosing-portrait.png](../.runtime/ol-college-ui-review/current/04-choosing-portrait.png) 与 [05 完整页](../.runtime/ol-college-ui-review/current/05-choosing-portrait-full.png)：390×844 下，自己四将加 AI 四将的面板高 1445px，两个确认按钮绝对 y 分别为 1003、1645；整页高 5587px。下面继续保留大厅座位、规则、图鉴和房间设置。
- 代码原因：`doudizhu-panel.ts` 把面板插在 `.room-grid` 前；`room-page.ts` 仅在取得原生 matchId 后进入 `in-match`，才隐藏房间网格／头部。最需要专注的赛前计时阶段仍沿用大厅文档流。

**建议：** 从赛前候选创建起，直接进入独立的比赛舞台；大厅横幅、设置和全图鉴移出主流程。阶段、操作对象、倒计时、候选和主操作留在可见区域。等待别人的时刻也继续显示这个舞台，不能退成宣传首页。这是当前共同路径的首要可用性问题。

### P1：自己与 AI 的两席候选变成长表单，缺少明确的任务顺序

当前 `for (const seat of state.seats)` 顺着服务端列表堆叠整块候选。补拍中先出现“AI队友”，自己在下一大段；与[原设计](ol-college-league-2026.md)要求的本人→AI顺序不符。每张卡重复“技能”和“换此将”，两组分别确认，玩家必须记住滚动位置、操作对象及剩余次数。角色确定后，页面仍只写“分别从每个席位自己的候选中选将”，没有直接告诉当前用户还剩哪一步。

**建议：** 一个屏幕只有一个当前可操作席位；顶部明确“你／农民”或“替 AI 01 选将／农民”，另一个席位用紧凑标签呈现“未完成／已锁定”。默认本人先做，再自动前进 AI；允许在两个合法席位间回看，已锁定只能查看。共用原来的选择期限，不重开第二段倒计时。本人／AI 的候选、选中值和两次额度分别保留。AI 地主只有一组六候选，直接写明本局将由你操作地主，不能保留待命席可选假象。

### P1：查看技能与选择互相打断，按钮位置会跳

[07-skill-expanded-landscape.png](../.runtime/ol-college-ui-review/current/07-skill-expanded-landscape.png) 展开一个技能后，[08-after-candidate-tap.png](../.runtime/ol-college-ui-review/current/08-after-candidate-tap.png) 点选候选便把技能关闭。测量从 1 个打开详情变成 0，整页从 4180px 缩到 4084px，当前确认按钮上移 96px。代码中点选调用 `render()`，随后 `seats.replaceChildren()` 销毁候选树；请求前 busy、请求后更新也会走整块重建。

**建议：** 保留稳定的候选节点和选中状态，不因选中、换将或另一席确认重建全部界面。技能用一个固定的详情区／抽屉，显示当前查看武将的技能；候选卡保持同高。操作栏位置固定，写成“已选：某将｜换该将（余2）｜确认出战”，先选卡再换或确认。换将成功只替换对应槽位，并保留当前席位、滚动和焦点；若被换走的是当前选中将，清除选择并说明。确认按钮应包含对象和将名，例如“确认自己出战：某将”，避免对象错认。无需每次操作都增加确认弹窗。

### P1：当前阶段、剩余动作和超时结果表达不完整

叫分只有一句当前倍数与轮到昵称，没有稳定的四席进度；选将没有逐席完成摘要。倒计时位于面板顶部，滚到第二组候选后不可见；它跟随 800ms 网络轮询更新，网络异常时旧数字可能停留，使用本机 `Date.now()` 也会受设备时钟偏差影响。这是代码可见的设计风险，未在本轮注入时钟偏差测试。

**建议：** 头部固定“第 N 局｜叫分／选将／手气／对局｜剩余 XX 秒”；四席摘要只显示公开轮次、合法的叫分与确认状态，不显示对手候选。叫分栏在本人或代理席轮到时就近展示合法按钮，其他时候写“等待 B2 叫分”，禁止用空白按钮区表达等待。超时结果紧邻操作区说明。截止时间仍由服务端决定，客户端用服务端剩余时间加单调时钟显示，低频同步校正；断线标“正在重连，期限继续”，不可假装倒计时重新开始。

### P1：牌桌工具栏把所有功能当成同等重要

真实牌桌图与 [10-farmer-table-landscape-expanded.png](../.runtime/ol-college-ui-review/current/10-farmer-table-landscape-expanded.png) 显示：模式、房间号、比分、网络、声音、音量滑条、本局记录、托管、恢复、二维码、投降挤在同一行。`.match-toolbar` 采用不换行加横向滚动，玩家要移动整条才能找不常用的动作；比分也只是长标题中的一小段。新增工具和原生牌桌没有统一信息层级。

**建议：** 常驻只留紧凑比分／局数、本人的当前角色或代理对象、必要控制状态及“更多”。正常网络、音量滑条、二维码、完整记录等进入更多；网络异常在状态区主动浮现，恢复只在需要时突出。托管／接回保留易找的入口与明确状态。不要为了比分再在牌桌上叠一条大横幅，保持既有原生手牌与确认按钮的空间。

### P1：农民互看做成右上角文本角标，和席位关系脱节

`farmer-hands.js` 把 `<details>` 固定在牌桌右上 `top:48px; right:8px; max-width:46vw`，展开后用文本标签列牌。实际 [10 横屏](../.runtime/ol-college-ui-review/current/10-farmer-table-landscape-expanded.png) 与 [11 微信锁竖屏式旋转模拟](../.runtime/ol-college-ui-review/current/11-farmer-table-portrait-expanded.png) 可见面板压在右上对手区域附近，容易让人把牌与所在武将关联。现在仅四张已显局促，更多手牌的占用将随内容增长；长手牌占用属于代码推断，本轮未补造十几张牌的截图。

**建议：** 同局另一农民头像旁放“队友手牌 N”入口，位置随实际队友走；底部自己手牌上方的保留区域显示可收起的队友牌条。明确写“AI队友／真人队友 · 只读”，牌面采用可辨花色、点数、牌名的缩略卡，超过一行横向滚动，不挤压自己的牌。默认保留轻量可见摘要，用户可以固定展开；放大查看作为专门抽屉。小有效高度时优先收为入口，避免盖住任何席位或原生选择。原生复杂技能弹窗打开时可以临时收起，关闭后恢复偏好。查看牌的手势不得进入出牌选择，不能给队友牌附上自己的材料高亮。界面改善仍只消费现有定向只读数据。

### P1：AI 地主的“报名身份”和“当前操作者”没有清楚分开

实际 AI 地主牌桌保留 AI 昵称，顶部只显示通用高校模式和比分；用户从真人席跳入 AI 地主视角，缺少持久提示。原设计已经要求“替AI队友选将，本局由你操作地主”，当前 `doudizhu-panel.ts` 并未完整表达。用户可能误以为自己待命、AI 正在出牌，或将“主动托管”理解为控制另一席农民。

**建议：** 选将结束前给一条不阻挡的交接说明，进入后常驻小标识：“你正在操作 AI 01 的地主｜手动”。主动托管后改为“AI 01 地主由 AI 托管｜接回”，宿主确认生效时才更新。真人本人当地主、真人农民、AI 农民各有对应文案；农民互看不出现接管 AI 队友的按钮。这是本项目人机设计，无法从官方两张图直接照搬。

### P1：待命像被退回大厅，局间又像退出重来

[等待公开牌桌完成同步后的竖屏](../.runtime/ol-college-ui-review/loaded/12-standby-portrait.png) 与 [横屏](../.runtime/ol-college-ui-review/loaded/13-standby-landscape.png) 仍保留大横幅、房间表单和公开观战区。390×844 下，品牌区和横幅占到约 y=282，比分卡约 y=304–407，公开观战区从约 y=420 开始，实际角色卡约 y=706 才出现，首屏仅容纳第一张卡的一部分；横屏首屏仍几乎只有横幅。牌桌已经正确同步，主要问题是其位置与表现没有成为待命者的主视图。`current/12–13` 另外保留了首次同步前的占位，不把它误报为“始终没有公开牌桌”。其他真人操作地主时，待命者需要在同一比赛上下文里理解当前角色、回合与比分，而不是回到大厅长页寻找。

当前局间比分是一段文本；结算主操作写“回到房间，准备下一局”，另有“结束整场练习”。没有集中说明谁赢本小局、为何加分、更新后的总分、下一局先叫位以及是否加赛。返回后又进入大量冻结的房间设置，增加中断感。

**建议：** 待命继续留在比赛舞台，显示“本局待命｜队友 X 为地主”，使用同一比分头和公开牌桌投影，记录作为次级入口；加载／恢复要说清当前情况。保持公开数据权限，不能借此给待命真人看地主手牌。小局结束显示紧凑结算页：“A 赢本局 +4｜总分 8:4｜已完成3/6局｜下一先叫 B2”，再进入整场休息区。准备、等待房主或开始下一局是主操作，成员与赛制仍冻结；结束整场放次级菜单。整场结束单独显示胜队和最终比分，不能把小局胜利与整场胜利混作一个状态。既有准备和开局权限不因改文案而取消。

### P2：卡片识别、美术和可访问性在结构稳定后统一

当前窄卡把头像和长名称挤在同一个横向按钮里，出现不规则折行；默认 `secondary` 按钮重复用于叫分、卡片、换将，主次不足。队伍目前主要依赖 A／B 文本，选中仅靠边框变色。应统一头像比例、名字区和可点范围，区分未选／当前选中／已锁定／替换中；颜色同时配文字或图标。可借官方图的蓝橙队区，但不要复制大背景或用颜色独立表达身份。支持键盘和读屏状态提示，紧急倒计时不要每 800ms 重读整屏。动画仅用于当前席切换、单卡替换与锁定反馈，不能拖延提交或刷新期限。

## 建议的页面分工与连续流程

这是一套共享比赛外壳内的阶段切换，不需要每阶段完整导航重载，也不需要重写无名杀牌桌。桌面和手机共用相同状态；方向变化只重排呈现，不刷新候选、期限和控制权。

| 阶段           | 主体内容与主操作                                             | 不应占据主区域的内容                     |
| -------------- | ------------------------------------------------------------ | ---------------------------------------- |
| 房间准备       | A／B 两队各两人、本人和 AI 标签、赛制、准备／开始整场        | 完整规则与图鉴可按需打开，不持续铺满     |

| 小局结算／休息 | 本局胜队和加分、总比分、局数、下一先叫位、准备／下一局       | 混在图鉴与模式设置里的下一局入口         |
| 整场结束       | 胜队、最终比分、比分明细、回房设置下一场                     | 继续沿用“本局已结束”而不说明整场状态     |

```text
┌ 第3/6局    A 4 : 4 B    选将 42s                     更多 ┐
│ 你·农民 [待确认]  →  AI 01·农民 [待确认]                 │
│                                                          │
│ [候选1] [候选2] [候选3] [候选4]  │ 当前查看武将与技能    │
│ [地主时同一区域容纳6张，不合并其他席候选] │ 固定区内滚动   │
│                                                          │
├ 替谁操作：你  已选：候选2    换该将(余2)    确认自己出战 ┤
└──────────────────────────────────────────────────────────┘
```

手机竖屏不把这整个横向界面缩成小字：顶部比赛头与任务标签固定，候选四张按 2×2、六张按 2×3 排列；地主十选一用于普通斗地主，采用同一个有界候选区滚动。技能以独立抽屉／页层查看，关闭回原选择；底部固定当前选中、换将次数和确认。不允许整页把最后确认冲到数屏之后。横屏有效高度较小时，候选与详情分别使用内部滚动，头部与操作栏始终可见。手机锁竖屏旋转应与现有牌桌偏好一致，也保留竖屏呈现；不得为修赛前布局撤销已经确认的横握操作方式。

推荐对局层级：

```text
比赛头：第3/6局  A 4:4 B  [你·农民 / 你在代打 AI01·地主]   更多
原生桌面：              对手／队友，当前行动及公开过程
                         [队友头像旁：队友手牌4]
辅助牌条：              队友手牌（只读，可收起，不进入材料选择）
本人区域：              原生武将、手牌、技能、原生确认
```

辅助牌条必须在真实的 844×390、350px 有效横屏和微信锁竖屏布局中选定不会遮挡的位置；线框不是直接追加固定高度 DOM 的实施许可。优先与原生本人手牌区协调，空间不足时保持入口＋按需抽屉。待命沿用同样比赛头和桌面关系，但只用公开投影，不创建第四个玩家视角。

## 改版顺序与验收重点

1. **先完成比赛舞台和页面切换（P0）。** 开始叫分即收起大厅装饰／设置，固定阶段与操作栏；先在 390×844、844×390、350px 有效横屏演示，保证叫分、候选及确认不用在文档长页里寻找。
2. **完成单席任务与稳定选将（P1）。** 本人优先、代理对象明确，保留分席候选／额度，详情不因点击消失，确认位置不因技能长度移动；用本人四将＋AI四将、AI地主六将和普通斗地主十将验收。
3. **整理牌桌信息和队友手牌（P1）。** 工具收纳、比分常驻、代理身份清楚；队友入口依附真实队友，展开不盖人、不混入自己材料。以农民双方、AI农民、AI地主、刷新恢复和身份轮换验证权限。
4. **统一待命、小局结算和休息区（P1）。** 同一整场上下文，能理解当前谁打、得几分、还打几局、谁先叫；按既有权限准备下一局。待命只看公开信息，投降仍保留该成员原有投票职责。
5. **最后统一卡片、美术和触控反馈（P2）。** 不靠加边框／换配色掩盖以上问题。

实现验收应包含真人地主、代理 AI 地主、双农民代理选将、其他真人地主时待命、选将／手气／对局中刷新、长技能、剩余一次换将、共用期限临近结束、同分加赛和整场结束。接回／托管以宿主确认后的状态为准；候选、手牌和未公开信息不进入大厅快照或公开观战。桌面模拟通过后再做原安卓／iPhone 微信实机，记录浏览器工具条、旋转、安全区及误触。
