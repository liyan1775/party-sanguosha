# 山河图：首版调研与接入方案

更新日期 2026-11-20。v0.10.0 为三章可通关的单剧本首版，开放普通、中等和困难各五档。完整征程与首领形态的实跑范围见[开发交接](handoff.md)。

## 三章首版的开放范围和结局

v0.11.0 在各自的城池池中加入长命难锁 1906、怀璧其罪 1907、荒庙遗宝 1933／1934、锦囊妙计 1954／1955。各项效果在出征时冻结，以选项编号绑定物品或铜币。风矍 22444／2444 使用皮肤 1000397，新手发二摸一，常规发四摸二，常规从困难起新增斩腕。小平津 2667 困难增加 939 咆哮。山河册探索目标是单机解锁安排，技能和战法效果取冻结的本季技能表。两个不同的第二章城池以各城原生关底胜利计。

v0.10.2 为当前 86 组遭遇及 15 个队友配置接入 75 张 OL 牌桌立绘，包含首领第二形态。按固定配置中每个出场位置的角色名、武将编号和皮肤编号核对。同一编号的羽林军、游侠、校事典刑官、天子近卫使用不同的图，张牛角与隐士张梁则按原表共用一张。原图由玩家电脑首次准备时从 OL 获取。[来源、角色与文件校验值](../config/shanhetu-portraits.json)

v0.10.1 补入第三章奇遇「林中岔路」的两种奖励配方。左边小道展示战法，右边展示装备，绕开密林分别获得140或210铜币。两种配方来自事件1956／1957，原表地点池为23、24、25、27，当前开放城池对应洛阳、河内和酸枣。噩梦的广成关 → 函谷关 → 崤函道路线已核对，两座新城分别有四组常规首领，特殊结局原表分别为噩梦档的「功成不居」和炼狱档的「震古烁今」。[事件与选择观测](https://s.xiaochao.org/data/events.json)

三章首版开放十二城、86组战斗配方，包括两种可以自行决定是否开战的奇遇。高难开放情况采用对应返场公告与实际游玩记录。冻结客户端把第16档写成关闭，OL的10月15日更新公告明确开启噩梦。函谷关、崤函道从第16档进入，仍属本地缺项。[官方更新公告](https://www.sanguosha.com/news/20261014_1695_1010)

山河册在终局保存结局名称，老记录可继续读取。普通1要求声望非负且智谋大于30，中等1要求声望非负且战功大于15，困难1要求声望非负、商才大于60且累计收入至少4000。支出不减少累计收入。通关未满足特殊条件时显示「大获全胜」，败北显示「折戟沉沙」。噩梦和炼狱的结局随对应难度接入。

判定对照 S5 原表501至504及2026-10-20生成的15,443次征程统计。三个特殊胜利结局分别有53、65、702个样本，对应难度均为1、6、11。困难样本中存在恰好获得4000铜币的胜利。已接决定的属性变化按选项编号核对，使用该选项有一致观测的增量。退军、重复提交与战斗重开不会多记结局或属性。[玩家实测汇总](https://s.xiaochao.org/data/analytics.json)

## 已确定的首版方向

用户要求接手项目，最终增加《山河图》模式。该要求接续此前已经完成的自定义将池工作，并优先于首发准备期暂缓新增模式的历史安排。

2026-11-07用户确认采用OL单人PVE原玩法，优先资料／现有实现最完整的剧本，并允许搜索视频平台、GitHub和社区资料。首版依据本轮可取得的资料选定**2026返场诸侯伐董（社区称S2）**。这属于用户委托的技术选型，未声称穷尽全网或所有内容已经支持。

首版围绕单人出征、章间分路、奇遇／商店／营地、战法与额外技能构筑、随身牌／装备、首领及征程终局完成闭环。房间真人数与关卡敌人数分别建模，玩家仍从手机操作，电脑继续提供固定无名杀规则与原生AI。

内容基线采用2026-11-07实际取得并冻结摘要的官方公开配置；社区JSON与源码索引用于检索和交叉核对。官方客户端源码仅静态读取其配置加载方式，不成为本项目运行依赖。

不同剧本和返场规则分别保存，2024同名初版及2017多人同名活动不与2026返场合并。原生文本、来源条目与真实效果逐项核对，未完成执行的内容不进入实际奖励或敌军池。

### 招募与初始队友

诸侯伐董的普通与精英帮手在`Adventure`、`Choose`及`General`分别对应事件、费用与角色配方。`UniversalGroup`按城池同时列出`fightgroup`和`premisegroup`，因此招募可追溯至各章城池池。原表六项已接奇遇均为免费普通帮手、400铜币精英帮手或谢绝领200铜币。固定预览在每章预留一个招募地点，队友会在后续战斗按配方满血参战。初始战法和光盟使用独立的特殊队友池。[2026返场开荒实测](https://game.xiaomi.com/viewpoint/1624366642_1791880781253_13)

### 山河册依据

原版冻结客户端把`DifficultySelection.reward2`读取为`TalentPoint`，普通五档均为10。`saijitianfu`记录研习节点、价格及前置，客户端的`getLockState`逐项要求前置齐全。`saijilevel`的六槽品质上限为普通、普通、稀有、稀有、史诗、传说，累计图册消费门槛依次为0、0、0、200、400、600。旧预览接入节点1、2、3、5、7、15，其余单机成长以2026-11-16要求为准。

和光盟的`strpra`为曼珠、阿绫、风篁、赤炼分别给出10、0、10、10。预览使用正权重的三名队友，固定起手按冻结`General.carddesc`与`sys_playcard`的牌种、花色和点数核对。开荒文章观察到的个别队友起手与配置有差异。固定实例使用本机135张无装备循环牌堆之外的发牌来源，弃置前销毁。传承在出征选将后由已接稀有技能池三选一。实跑及逐技能覆盖见handoff。

### 普通档新增关底

本轮新增黑山匪害、其实难副、祸国凶贼、枪王张绣、夺目一箭、文远之威、华雄耀武、俊彦曹操、忠烈双卫、盟中夏侯、谋臣双璧、白马将军及西凉暗军。地点可抽到的首领来自该城`Level.eventfight`，阵容和技能取各自`Fight`及`General`行。华雄的新手组22647配专版耀武和势斩，常规组2647配红杀来源选择回复或摸牌的耀武。

郭汜的黑桃2斩魂刀、张绣的黑桃A雷震、张辽的方片5刑天破军斧按公开快照的`General.t`、`sys_playcard`与`cha_spell`绑定。三把武器均在首轮前经原生装备事件进入装备区。于毒的中毒以受害者准备阶段判定，成功解毒后可再次获得。归心从其他角色现有可取得牌的区域中随机取一区；神速在对应阶段执行，按本次及本回合已跳过的原生阶段计算加伤。公开技能文本留下的时机边界按本机原生事件处理，实跑和分支覆盖见handoff。

大谷关的英武壮志2635／22635和洛阳的智勇双杰2669／22669保留在源表缺项。龙卫仍需确认开局随从及召唤候选，动荡仍需确认狂暴枪王何时入场和接管回合。

### 中等档分路

按`Chapter.openDiff=6`和`canGoTo`开放广成关→伊阙关→洛阳、虎牢关→小平津→洛阳。两城地点用`Level`原坐标，常规战斗和招募仍在各自`UniversalGroup`取样。伊阙关关底为年少风华、黄巾余匪、代汉涂高、江东猛虎。小平津关底为悍将朱灵、河北双雄、凉州猛将、幽燕双骑。两城中等档已接齐原表关底，普通战斗增加杀良冒功、敌兵奇袭、杯弓蛇影和皇室物品四组新手／常规配方。场景地形从困难档起处理，参见`Common.scenespellneeddiff`。

中等新增的装备、体力和技能取自同版原表，对应技能时机接在原生事件上。虎烈根据该次牌是否造成伤害决定能否令目标反击，宦浮读取该次杀对原目标造成的伤害量。急陷要求合法攻击范围，按选定时的三项条件数摸牌。颜良文丑转换牌时按本轮双雄发动次数设决斗伤害。张燕的炎狱最多判定三次，蔽日按实际恢复值摸牌。单项实测触发范围见[开发交接](handoff.md)。

### 困难档分路与地形

`Chapter.openDiff=11` 增加两组分路。广成关经颍川郡到酸枣，虎牢关经荥阳到河内或酸枣。颍川郡和河内为平原，荥阳为城池，酸枣为战场。`Level.scenespell` 给出各地点的地形，`spellTarget=0`作用于全场。地图按 `Common.scenespellneeddiff=11` 显示当前与目的地地形。描述取自同版`cha_spell`。

| 地形 | 全场效果                  |
| ---- | ------------------------- |
| 高山 | 回合结束时流失1点体力     |
| 密林 | 出牌阶段最多使用10张牌    |
| 平原 | 出牌阶段可多使用1张【杀】 |
| 河流 | 手牌上限至多为8           |
| 城池 | 与其他角色距离减1         |
| 战场 | 摸牌阶段多摸2张           |

困难1至5的体力、发牌、摸牌与出杀数值各取对应的`DifficultySelection`行。困难4额外初始护甲1，困难5额外初始护甲2。`EnemyDiffGrowth`另给第一章体力1，第二章体力、手牌和出杀次数各1，第三章再给摸牌、初始护甲及护甲回复各1。这些数值与当月增长合计后按敌军人数缩放。公开客户端的护甲提示说明每轮回复，`General.maxarmor`在已接配方均为5，本机将回复安排在原生轮开始事件。

困难武将的`att_KN`、`getspell_KN`、`equip_KN`和`carddesc_KN`在原累积档级上应用。东吴宿将的程普和韩当各加发指定的黑桃A【杀】。华雄的耀武换成按伤害牌颜色摸牌的版本。当前新增接入十组源表首领，颍川郡四组，荥阳、河内、酸枣各两组。黑光铠从应变定义包读取。涉及金乌落日弓、三首与动荡、妖刀赤瞳或新版咆哮的难度变体，以及新城剩余六组首领，待核实执行细节后再进入各城的抽取池。[源表准入记录](../config/research/ol-shanhetu-2026-11.json)

## 固定引擎的可复用能力

`noname/library/zhanfa.js`包含`ZhanfaManager`和169个顶层战法定义，`Player`提供`hasZhanfa`、`addZhanfa`及`removeZhanfa`。其中显式`shanhetuList`只列勤勉、天人合一、全力三个ID。169是静态定义计数，既不代表全部来自山河图，也不代表已经完成本项目的联机、隐私和恢复验收。

`character/collab.js`的`collab_shanhetu`分组目前只有`ol_re_nianshou`。名称分组和角色库存不能替代模式，也不能据此直接扩大666个已接入角色的可选库。

新增`audit-shanhetu-sources.mjs`按固定引擎静态解析4655条技能说明与169条战法定义，不执行第三方源码。S5公开数据的329条战法中，84条在相同名称下与原生说明去除显示标点后相同；关联敌军的771种技能中，17种获得同等文本候选、611种仅有同名候选、143种未命中。这里的771包含各难度及额外技能，不能理解为每场需要771种技能。相同文字也只是复核候选，脚本不生成产品白名单；同名、相近效果和相同作者都不能替代版本核对。

本机固定目录有`boss`、`brawl`等其他模式，但目前没有依据证明其等同山河图。正式服务只允许已接入的身份、斗地主、2v2、单挑及高校练习；`bootstrap.js`、`mode.js`及资源路由均按这些模式处理。直接改一个枚举或将山河图映射为现有单挑，无法实现关卡及成长。

资源清单只有通用`image/card/zhanfa.png`，尚未接入`image/zhanfa/`下各战法图片。若使用原生战法显示，必须核对固定资源和路径，或者在适配层提供明确的同源文字显示，避免出现缺图和局域网外网依赖。

山河图采用独立牌堆。标准与军争161张模板剔除26张装备后为135张，这是按公开无装备规则选用的本地模板。随身牌从官方Card与sys_playcard表核对95项基础牌与装备，保留花色点数及autoequip标记，每战新实例、进入弃牌堆前销毁。普通1预览已串联三章地图、13项额外技能、19项战法、必选奖励、满槽替换和集市刷新。实际触发与恢复覆盖见handoff。

人数、首剧本和来源选型已确定，分层约束记录为[ADR-049](architecture.md#adr-049山河图单人征程与来源版本隔离)。具体战斗内容继续按证据和执行覆盖逐步接入。

现有高校整场流程证明可以把多个原生战斗组织在同一房间，但其胜者协议只有地主／农民，不能直接用作PVE结果。山河图需要绑定征程、节点、战斗实例和唯一结果；重复结束、过期结果、用户离开或宿主失败都不能重复发奖励或跳关。

房间成员与关卡内敌将分别建模。敌将是规则端控制的角色，不能领取真人会话、成为房主或挤占手机玩家报名位置；电脑继续只提供服务。本轮不新增真人合作规则。

## 快照与复核命令

10份公开JSON仅存于忽略的`.local/research/shanhetu-20261107`，受版本管理的研究配置保存URL、字节数、SHA-256、场景计数和源码commit。公开配置站更新后，下载器拒绝用新内容替代冻结版本；已校验本机快照继续可用，不能保证外站永远提供旧字节。

```powershell
npm run engine:research:shanhetu
```

命令只获取／校验研究数据并与固定引擎比对，不启用模式、不改变房间或本机将池。报告写入`.runtime/shanhetu-research/native-coverage.json`。也可用`node scripts/audit-shanhetu-sources.mjs <本机快照目录>`单独复核。

进一步取得官方公开`Config.sgs`（4178291字节）和网页客户端`sgsGame_a.sgs`（5406286字节）。静态读取客户端配置加载方法中的字节参数，使用Node原生AES-128-CFB及gzip在本机解析`hd_roguelike.sgs`，未执行客户端JavaScript、未登录商业服务。ZIP中央目录、成员大小、CRC32、归档／成员／解码结果SHA-256均核对；解码结果5225207字节、SHA-256为`0e116ac3091748127e104878e01daddaf6cdb847d5b4f2cafa836a4223accca2`。

```powershell
npm run engine:research:shanhetu:official
```

该命令核对／获取两个冻结公开归档并静态解析，报告在`.runtime/shanhetu-research/official-config.json`，原JSON留在`.local`。它不载入商业客户端或改动本项目运行引擎，归档版本变化时拒绝替换固定版本。

公开表共41项，包含章节、地点、通用遭遇池、条件、敌军、战法、技能、卡牌、商店、营地、成长、难度和结局等。S5章间14区连边及首领门槛直接核对，三章基础天数／门槛为4／6／7；具体增减天数的技能另行解释。原始Adventure有1062条，社区JSON有1059条，差出的1031／1032／1033只记录为源差异，未凭条目名推测效果。字段及配置存在不代表服务端随机算法已公开，也不代表战法与敌军技能已经在固定无名杀实现。

同一冻结归档的`cha_spell.sgs`现已用相同加载方式静态解析，解码1174557字节，SHA-256为`0286c6c209ae91ecaac29d3f2e31c985a7c8a11c0423066ec0d1c97ab7b5536b`，包含3125条技能原文；工具同时核对已接苦肉3297所指原技能62的名称／全文。此原表可核对山河图专用141xx技能及普通同名版本，仍不自动批准执行或把额外说明表打包给玩家。

## 完整流程与验收顺序

1. 明确一个剧本、首版难度与规则表，记录完整可用名单和缺项；不把推测参数标为官方参数。
2. 接通一个真实PVE战斗，验证合法选将、发牌、敌方原生AI、敌我胜负、原座位刷新恢复与私有牌面过滤。
3. 串联连续战斗和成长：上一节点结算一次、选择奖励／路线、下一战实际取得对应效果；失败结束征程，不凭手机提交的胜负推进。
4. 完成选定范围内的地图、商店、营地、奇遇与首领，核对铜钱／成长上限及拒绝非法、重复、跨房和过期操作。
5. 验证刷新、短断线、战斗中断、战斗外返回、征程终局及重新开始；再跑现有模式回归，记录桌面模拟与微信真机的区别。

“战斗外续征程”与“服务重启保存”是不同能力。当前房间重启即清空，`data/rosters`只保存将池；山河图若需要跨服务重启继续，应独立定义本机征程摘要、所有权、版本迁移和删除方式，不保存裸cookie、手牌、牌堆或原生执行对象。不能把资料放到`.runtime`后承诺持久恢复。

内部验证命令为`npm run engine:verify:shanhetu`，需要完整固定资源及Edge；可用`SHANHETU_VERIFY_DEFEAT=0`只跑连续胜利部分。验证用新手普通1的22498／22298真实阵容，奖励／营地构成合成短路线以检查状态传递，不能将其作为正式剧本。当前部分战法只核对取得与恢复，未触发的效果继续单独验收。详细失败、修复及通过证据见handoff当前节。

首领场景可用`SHANHETU_VERIFY_BOSS=lvbu|liru|taishici|lijue|yujin|yuanshao|lijue-normal|lvbu-normal`，`SHANHETU_BOSS_GROWTH=0`使用基础成长以增加敌军行动覆盖。手机流程设`SHANHETU_VERIFY_FULL=1`与`SHANHETU_VERIFY_NORMAL2=1`后，可验证普通1通关解锁并实际出征普通2。李儒空手分支、无费用灭计及两轮焚城另与社区实现的机制解释交叉核对。[固定版本的社区S5专项](https://github.com/xincheng213618/sanguosha-dotnet/blob/d7bcc5b1110629e551949d9103f911a642fc412e/tests/CardGame.Core.Tests/ShanheLiruSkillChecks.cs)

第二形态可用`SHANHETU_VERIFY_ENCOUNTER=rage-stage|shengui-stage|niufu-stage|dongmin-stage`单测，`SHANHETU_VERIFY_DIFFICULTY`可选3、4或5。测试在实际变身后短暂停住流程以刷新客户端，然后继续原生自然出牌。手机流程追加`SHANHETU_VERIFY_NORMAL3=1`可继续验证普通3出征与下一档解锁。

验证继续遵循项目的真实引擎确认要求：大厅、协议夹具和领域测试各说明范围；对局结论必须有原生选将／发牌及实际规则执行。当前调研不新增可玩、全战法兼容或真机通过结论。
