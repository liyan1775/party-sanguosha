# 开发路线

按可验证结果推进，未估算排期。完成状态以 `handoff.md` 为准。

## M0：项目底座和扫码大厅

- [x] Git、目录边界、接续说明、忽略本机运行文件。
- [x] 记录四种玩法、人数、单武将单挑、两档武将和 AI 要求。
- [x] 电脑服务页与主页二维码，不预建房间、不赋予电脑房主权限。
- [x] 玩家主页建房自动入座成为房主，房间列表、独立房间与跨房间权限隔离。
- [x] 所有入座成员展示直达房间二维码，昵称、准备、刷新恢复、断线状态。
- [x] AI 席位逐个添加、补满、移除、自动准备；席位变化真人重新准备。
- [x] 房主显式离开交接，最后真人离开关闭房间；临时断线保留身份。
- [x] Windows 双击启动/停止、浏览器打开、实例复用、端口冲突处理。
- [x] 引擎研究候选、真人/AI 适配契约和自动化验证。
- [ ] Android/iPhone 微信实测扫码建房、成员分享和断线恢复。

验收：一台电脑展示主页码，独立手机会话建房、参赛、分享房间码；5/8 席可用 AI 补足。开始拒绝未就绪引擎，AI 席位不当作已实现 AI 出牌。

## M1：最小真实对局与原生 AI

- [ ] 选定能在局域网浏览器运行、可固定版本的无名杀基线。
- [ ] 下载/校验、完整资源、预编译、同源 HTTP/WebSocket。
- [ ] 电脑规则宿主不占参赛席位，玩家房主保留手机上的管理与参赛身份。
- [ ] 单武将单挑：一真人 + 原生 AI 先验证完整选将、出牌、技能和胜负。
- [ ] 两独立真人会话完成单挑：从扫码到结算、回房、再次开局。
- [ ] 原生 AI 完整决策配置核查，隐藏态度/智力选项，避免假 AI。
- [ ] 真人/AI 身份绑定、动作权限、私有信息与真实游戏重连。
- [ ] 单间真实规则状态隔离及可支持的并发房间数量验证。

验收：电脑不参赛；两真人单挑与一真人一 AI 单挑均完整结束，资源全由电脑提供，断线能恢复本人对局状态。

## M2：四种玩法与两档武将

- [ ] 斗地主地主 +1 体力上限、飞扬、跋扈；不引入额外强化。
- [ ] 2v2 选将、座次、死亡奖励、团队胜负。
- [ ] 5、6、7、8 席身份；全真人与混合 AI 场景，电脑不计入人数。
- [ ] 真人和 AI 的两档选将池严格生效，手机菜单不能额外开启武将。
- [ ] 阴/雷分组、12 神将白名单、模式特殊限制验证。
- [ ] Android 与 iPhone 微信分别完成四种玩法，覆盖横竖屏、后台恢复。

验收：四模式可完整对局并再次开局；AI 使用原生决策；进阶档不混入其他神将或整个风火林山普通包。

## M3：扩展与聚会发行

- [ ] 扩展 manifest、版本、引擎范围、浏览器/联机兼容检查。
- [ ] 电脑统一分发扩展和资源，全部手机版本一致。
- [ ] 房主开局前启用扩展；运行锁定；加载失败恢复。
- [ ] Windows 可携带发行包，包含运行环境、引擎和资源，首次使用也无需命令。
- [ ] 离线准备、端口与网络诊断、开局速度与资源大小测量。
- [ ] 第三方来源、许可证、升级步骤与开发接续文档。

验收：聚会当天不用联网安装，双击启动后扫码玩；其他开发者能按文档增加一个扩展并验证联机。
