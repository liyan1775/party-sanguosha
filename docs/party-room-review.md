# 将池维护：需求、实现边界与验收

更新日期：2026-11-04。当前源码v0.9.0，固定无名杀v1.11.6／commit `2367607e246d21aae168dba15c01151ee0651f30`。最新运行和验证结果统一见[开发交接](handoff.md)，架构见[ADR-048](architecture.md)。

## 本轮确定的目标

用户明确新鲜感来自武将将池，最终将本轮收敛为“自定义将池，项目玩法本身无需修改”。主代理负责技术选择、协调、集成和验收，用户只回答需求问题。官方月份检查更新属于后续导入便利功能，本轮交付网页中可以直接维护和使用的自定义名单。

原流程将名单、共享枚举、图鉴与构建绑定，修改通常需要开发者运行生成器、构建和重启。v0.9.0把用户资料和内置配置分开，允许保存后直接用于等待房间。可选目录为当前12池中去重的666个已接入原生ID；1342条图鉴记录因跨池重复而更多，固定引擎的2563项发现目录不能直接当作已可玩库。

## 已实现的使用流程

1. 房主在等待房间的武将设置中打开“自定义将池”，新建空白草稿，或复制内置／已保存名单。
2. 按武将、技能、势力、包和具体原生版本搜索，跨原有将池勾选；详情显示完整原生技能和ID。同名版本分别保留，不自动替换。
3. 可以仅看已选、按名单批量加入／移除或明确确认全选当前搜索结果。列表分批显示48项，勾选跨筛选和后续批次保留。
4. 命名后“保存名单”只保存新修订；“保存并用于本房间”另行应用。非空但不足当前玩法开局的草稿可以保存，应用时说明所需人数／候选容量；错误保留草稿。
5. 自己保存的资料可编辑和归档，其他入口可以复制。编辑追加新版本，不改旧版本；列表分别显示本房绑定和最新版本。切回内置档明确清除自定义引用。

手机图鉴、点将、斗地主赛前候选、公共素材预加载及原生服务读取同一绑定版本。转交房主或进入对局后，前端禁写并保留草稿，后端继续独立鉴权。

## 玩法与数据边界

- 自定义只修改角色白名单，继承创建／复制来源的基础规则档。原牌堆、主公与其他席位候选上限、队伍共享选将、地主规则、手气、完整技能和AI不改。高校仍固定赛事名单。
- 单挑沿原算法最少两将可各1候选、每席最多5名；2v2须两队各10候选，普通斗地主须地主10／农民6。身份主公仍5／10选1，其余按原余池均分，不足时不能偷偷补进池外武将或额外扩大主公候选。
- 多源组合按已有预设登记的依赖来源解析并保持确定顺序，不凭名字猜技能闭包。原生服务重核ID、依赖、commit和摘要，继续使用privacy过滤、物理卡牌引用保护及原期限恢复。
- 名单在电脑`data/rosters`持久保存；停止服务仍清空房间。编辑能力随同浏览器／入口的一年期HttpOnly cookie保留，磁盘仅存摘要；公网域名改变或换入口时可复制继续编辑，无需账号。
- 原子保存、备份和完整性校验失败时保留旧资料。库上限100份、每份1000版本、磁盘资料16MiB。data不进入Git或发行包，升级应保留；目前没有网页导入导出或自动修复损坏资料。
- 保存新版本或归档不改变已绑定旧房及进行局。归档阻止新应用，历史版本仍可供旧绑定读取。用户库不授予电脑玩家房主权限，也不能跨房操作。

## 接续时的研究依据

之前以11月OL排位为例核对了官方来源，保留为后续导入工具的研究资料。[官方公告](https://www.sanguosha.mobi/news/20261027_4744_0516)于2026-10-31发布，含完整HTML基础／进阶表，说明新增11项、删减18项。新增项中7项有既有OL映射且已接入，3项有原生候选但尚未接入，1项需核OL具体版本；此为窄范围预检，不是11月完整池验收。可恢复数据见[研究配置](../config/research/ol-ranked-update-2026-11.json)。

后续官方更新应展示完整名单、增删和冲突，复用同平台已审版本，不能用同名魔曹操、羊祜或跨平台缺项结论代替核对。本轮自定义库不自动标成“官方11月已完整导入”。

最初现场审查使用独立NativeNonameService和390×844内置浏览器，完成主页建房、等待房、原固定将池保存和点将。初始5席房设置顶部约1929 CSS px，提示旧页面配置入口较深；这些配置截图不当作游戏对局证据，保存在`.runtime/project-takeover-20261104/screenshots/`。新功能最终截图与交付证据以handoff的新记录为准。

## 委派与成本选择

研究阶段使用Luna/high盘点和独立审查、Sol/medium查来源与实现手机界面、Sol/high审查并实现后端，实际引擎接入另委派Sol/high。主代理统一接口、复核代码、处理产品边界和运行验收；各自文件范围明确，未并行修改同一组件。模型分配依据已核对的[OpenAI官方子代理说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)和[模型选择说明](https://developers.openai.com/api/docs/guides/model-selection)。没有账单数据，不计算实际金额、token或节省比例，日常自定义名单维护也不依赖付费AI服务。
