# 开发交接

最后更新：2026-10-04，当前版本 v0.2.0。

## 当前状态

M0 大厅原型已按用户最新说明修正。**尚不能进行真实三国杀对局或原生 AI 出牌。** 可以在手机建房、成为参赛房主、分享房间二维码、管理 AI 席位与准备；开始按钮因引擎未接入而关闭。

本地 Git，无远程仓库或云部署。技术栈为 Node.js 24、TypeScript、原生 HTTP/SSE/DOM、esbuild、本机二维码；没有引入线上依赖服务。

## 必须延续的产品决策

- 电脑只提供局域网服务，双击启动自动打开服务页，显示**进入主页**的二维码；电脑不是房主，不占席位。
- 玩家从主页创建房间，自动入座成为参赛房主，在自己的手机上设置和开局。
- **所有入座真人**都可以展示直达本房间的二维码，不能限制为电脑或房主才能邀请。
- 同一 Wi-Fi/电脑热点，不支持流量跨网，不需要微信登录、账号或客户端安装。
- 身份局 5–8 席、三国杀斗地主 3 席、2v2 4 席、单武将单挑 2 席，一局定胜负。
- 斗地主地主体力上限 +1，获得飞扬、跋扈，无额外强化。
- 新手标准包；进阶界限突破 + 阴 + 雷 + 神话再临 12 神将白名单。
- 房主可添加无名杀内置 AI 补足人数，固定最强可用原生决策，**不提供智力选项**。AI 计入总席位、自动准备，不成为房主。
- 复用无名杀对局 UI，改善扫码、开局与手机操作。

完整需求见 `product.md`。v0.1.0 的“电脑房主/能力链接”属于已替换方案，不应恢复。

## 已实现边界与入口

- `/server`：电脑服务页，主页二维码、网卡选择与刷新、公开房间概况。
- `/`：玩家主页，昵称建房、房间列表、返回原房间。
- `/join/房号`：手机房间，同一个页面根据玩家会话显示房主控制。
- `LobbyStore` 管理多个独立大厅房间与会话所在房间；`RoomStore` 管理单间状态。服务启动时没有预建房间。
- 创建者自动成为真人席位和房主；服务端按房间验证设置、AI、移人与开局权限，其他房间的房主也不能越权。
- AI 逐个添加、一键补满、移除；减少席位自动裁掉多余 AI；真人超额则拒绝缩小。
- 设置或席位组成改变后真人准备归零；AI 始终自动准备。满房仍可通过同一 cookie 恢复本人。
- 最后 SSE 标签关闭后标离线并撤销准备；临时断线保留房主。主动离开交接给下一真人，最后真人离开关闭房间并失效邀请。
- 每位入座真人都可展示本房间二维码。二维码地址白名单、cookie 与 DOM 文本渲染均由本机服务落实。
- `NonameAdapter.ready` 为 `false`。`MatchSetup` 已包含真人/AI 席位、玩家房主 ID 和 `strongest-native` 策略；**契约不是已运行的引擎 AI**。
- 模式、AI、武将配置是产品要求，尚未用于真实游戏；扩展目录保持空列表。

网页逻辑拆在 `main.ts`、`lobby-page.ts`、`room-page.ts`、`ui.ts`、`qr.ts`，避免把不同页面继续堆入一个入口文件。API 与权限细节见 `architecture.md`。

## Windows 启停和本地文件

根目录 `启动聚会三国杀.cmd`、`停止聚会三国杀.cmd` 是非程序员入口。启动器需要 Node.js 24；本机已安装。已有依赖时离线构建启动；缺依赖时调用 npm 锁定安装，首次准备需要网络。便携包包含 Node 和无名杀完整资源的工作留在 M3。

启动器的 PowerShell 与 Node 代码在 `scripts/launch.ps1`、`scripts/launcher.mjs`。后台 Node 隐藏运行，关闭浏览器不会停止进程。重复启动通过当前实例健康检查复用服务；升级旧版本需先停止再启动。

`.runtime/session.json` 存服务页、公开主页地址、实例 ID、PID 和**本机停止凭据**，不会通过 HTTP 公开。不要完整打印该文件、提交 Git 或把停止凭据放入二维码。`.runtime/server.log` 和 `server-error.log` 为后台日志，`launcher.lock` 是启动互斥文件。

本机 3000 端口由其他程序使用，`.env` 指定 3001，没有终止其他程序。以当前 `.runtime/session.json` 中的 `serverUrl` 为准。双击启动在非显式 `PUBLIC_URL` 下可尝试其他端口；终端 `npm start` 不会自动改端口。

所有房间为内存状态，停止/重启清空；浏览器 cookie 只能恢复当前服务生命周期内的席位。微信和系统浏览器不共享 cookie，跨浏览器恢复仍需设计。
