## 已确定的产品约束

- 手机玩家创建房间，成为参赛房主；所有真人成员可展示房间直达码。
- 一台电脑保持开机、联网与页面开启；手机默认各自 Wi-Fi/流量扫码，局域网备用可离线。无需账号/好友/解锁/教学流程。
- 身份局 5–8 席，斗地主 3 席，2v2 4 席，单挑 2 席、每人一将、一局定胜负；总数包含 AI。
- 地主体力上限 +1，飞扬、跋扈，无额外地主强化。
- 新手为上游完整 standard（33 将）；进阶 refresh（128 将）+ 阴雷（16 将）+ 指定 12 神将，共 156 将。
- AI 直接使用完整原生事件决策，没有单独随机机器人或智力选项；difficulty 是态度，不能设 hard 就声称更聪明。
- 新手档 slow/1000ms、进阶 fast/500ms；只调整原生等待，不改变 AI 决策。loadConfig 会重设 duration，必须在 mode.start 再应用。
- 微信锁定竖屏时默认旋转横向牌桌，横着握手机操作；可切回竖屏，切换不刷新对局。
- 改配置/席位后真人重新准备；AI 自动准备。主动离开交接房主，临时断线保留身份，最后真人离开关房。

详情以 product.md 为准。不要恢复 v0.1.0 电脑房主能力链接方案。

## 接入边界

正式 main.ts 使用 NativeNonameService。默认不带 adapter 的领域/HTTP 测试仍使用未配置占位器；测试 fake 不能当作游戏可玩。资源校验通过、电脑服务页心跳在线才 ready，真实选将和发牌确认后才 playing。

状态 waiting → starting → playing → finished → waiting。手机选将发生在 starting；失败或规则宿主丢失回到等待，真人重新准备；结算后房主回房释放旧 worker、保留房间和席位，下一局创建新的 match。

规则宿主凭据为仅回环 HttpOnly cookie，手机对局凭据来自大厅 cookie；都不进 QR/公共 API。套接字按原有席位绑定 ID，拒绝跨房、跨源、原生配置/开局/牌堆/任意执行。原生昵称必须 textContent。

privacy.js 过滤接收玩家不可知的暗牌值、身份、提前编码的事件父链和重连状态；公开牌/原生授权查看保持可用。入站物理牌只按现有 ID 解析，不接受客户端改写牌值。原生技能的额外 storage 和全面恶意客户端决策校验没有穷尽验证；新增扩展要逐项补覆盖。

不要直接透传原生序列化：本基线的 cardInfoOL 含完整牌值，原生 UI 的牌背不足以阻止客户端获得信息。useCard/respond 的动画先于物理牌移动，须按事件材料识别公开牌；判定翻牌位于 player.judging，结束后位于 event.result.card，不能把 event.card 当作翻出的结果牌。ordering 也用于私人观星，不能整体公开；手牌过滤尊重原生 knowers（例如公开获得的洛神牌）。

五谷丰登的 useCard 父事件在移动前记录 wuguShownCards；只公开其中的牌。进阶回归发现涯角同样在移动前公开牌堆顶的一张牌，按 reyajiao/event.card 精确识别；任意其他 event.card 仍不公开。身份死后，上游 setIdentity(player.identity) 假设客户端一直持有秘密身份，适配必须先发送该阵亡者的真实公开身份并刷新 dieidentity；不改变原生死亡奖励。全员亮身份函数可能被广播，包装不能引用接收端不存在的闭包变量。

bootstrap.js 入口先显示分阶段状态，再动态导入引擎；两分钟载入检查和失败重试覆盖原生十秒 reset，不自动清空存储。package.js 仅枚举 definitionPacks，保留标准档 refresh/sp、进阶档 standard/yijiang/tw 与额外造牌依赖，选将仍为 33/156、牌堆仍为标准。静态 AST 检查不等于所有动态技能路径已穷尽验证。

同一 cookie 刷新恢复本人；短暂对局连接中断由外层恢复 iframe。上游在离线期间可临时用 AI 行动，重新连上恢复人工控制。跨微信/系统浏览器不共享 cookie；服务器重启清空对局与大厅。

## 启动与接续

非程序员：根目录启动/停止 .cmd，默认跨网络；「启动局域网聚会三国杀.cmd」为同 Wi-Fi 的备用。完整包解压后用相同入口，无需安装或额外下载。源码版首次准备需要 Node.js 24 和网络，固定联网组件也会自动准备，之后校验缓存。两种入口共用本目录实例，切换先停止。公网连接失败时电脑页收码，再次双击可以重试；有牌桌且组件退出时不换域名冒充恢复。

工作区 .env 使用 3001；端口占用会变化，不要按端口或批量 Node 杀进程。当前服务以 .runtime/session.json 中的 serverUrl 为准，停止脚本校验实例与本机控制凭据。不要完整打印 session.json，它含停止 token；不用于游戏存档。

升级需要完整停启并刷新手机；停止清空大厅。版本不匹配时启动器要求先停止本目录旧实例，不要为了版本显示中断正在玩的房间。新版网页兼容旧 `/api/info` 的缺省局域网元数据，mode.js 只在服务器声明支持时载入新传输模块，避免构建期间损坏旧实例。

开发：npm run check；页面变化 npm run test:browser；原生改动 npm run engine:verify:rooms，按 runtime/README.md 分别补 advanced、8 席、两真人、手动、重连、第二局与判定定向测试。上游或资源变更后重新准备/校验，更新固定来源与验证矩阵。

下一项：继续记录微信复测的设备、玩法与网络路径，覆盖不同 Wi-Fi/流量混合玩家扫码、直连中断、后台/切网恢复和原房第二局；iPhone 单独验收。继续复核局外预加载、八席开局、语音无积压、南蛮/万箭/乱武提示、阵亡身份、判定和五谷。此前 Android 微信流量单挑及 v0.4.0 载入/声音优化已有用户确认；本次局域网体验已获用户确认恢复，但模式和网络覆盖范围未记录。5–8 席全真人、多房容量、进阶技能额外私有 storage 和扩展加载尚未穷尽覆盖。临时公网路由仍影响非直连玩家的往返时间，未承诺消除所有 1–2 秒等待；固定域名/长期在线另行设计。
