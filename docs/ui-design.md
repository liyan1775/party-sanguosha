# 无名杀界面的轻量实现与动画

日期：2026-10-06。状态：已被 v0.6.3 恢复无名杀原生 UI 的用户决策取代。以下保留 v0.6.2 的轻量研究与实现记录；默认牌桌不再采用此方案，当前方向见 product.md 与 ADR-022。

## 已确认的方向

用户评审后明确：保留无名杀的界面和动画体验，用代码代替体积大的装饰素材以提高加载速度。原方案偏向独立设计，又把过渡缩短到 100–300ms，偏离了这一目标。该方案和 `ui-preview.html` 的短动画演示已被本文件取代；旧演示仅留作研究记录，不能代表当前实现。

实现以固定无名杀 v1.11.6 为参照，commit `2367607e246d21aae168dba15c01151ee0651f30`，来源见 [引擎配置](../config/noname-candidate.json)。参考其席位与手牌关系、牌面信息、选择状态、飞牌、伤害浮字、技能提示和回合反馈。原始第三方代码、资源和许可证保留，不修改 `.local/noname` 引擎源码。

手机继续使用声明式轻量视图，完整规则、AI 和原生选择在电脑运行。代码绘图是资源优化手段；不能据此取消过程动画、重写卡牌规则或改变玩家熟悉的交互。

## 调研依据与取舍

| 依据                                                                                                                                          | 对本项目的作用                                                                                   |

| 当前轻量代码与真实 Edge 手机尺寸对局                                                                                                          | 节点随快照重建会打断焦点和过渡；只有最终状态不能准确还原使用、响应或伤害过程                     |
| [三国杀 OL 互通版官方介绍](https://www.sanguosha.com/act/mobile/)                                                                             | 经典牌桌的识别关系。旧介绍不作为当前商业客户端功能或性能证据                                     |
| [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[Material Motion](https://m3.material.io/styles/motion) | 反馈应明确、可打断，文字和最终状态可独立理解；时长需服从对局节奏                                 |
| [web.dev 动画性能指南](https://web.dev/articles/animations-guide)                                                                             | 优先小范围 transform/opacity，控制短期效果数量，避免大面积逐帧布局和重绘                         |

## 资源与布局

| 元素                           | 轻量实现                     | 保留的体验                               |
| ------------------------------ | ---------------------------- | ---------------------------------------- |
| 牌桌底纹与装饰                 | CSS 渐变和小 SVG             | 原生的低对比底色，武将和卡牌成为视觉中心 |
| 边框、按钮、选中轮廓           | HTML/CSS                     | 稳定位置、抬牌与选中反馈、独立确认       |
| 体力点、护甲与状态             | CSS 与文字                   | 原生绿色体力点、清晰数量和公开状态       |
| 牌背、飞牌、目标指向、技能光环 | CSS/SVG/Web Animations       | 有来源、目标、移动、停留和消失的过程     |
| 武将原画与卡牌插画             | 现有压缩头像、原插画按需加载 | 角色与牌的辨识度，不用代码近似复杂原画   |
| 语音和音效                     | 原资源按需加载，丢弃过期播放 | 与当前对局相关的声音及玩家自己的声音偏好 |

主参照为 844×390 横屏，并覆盖 350px 有效高度、8 席和竖屏备用。对手按原生座次在上方；本人武将在左下，手牌紧邻本人武将，确认与技能在下方；公开牌与选择提示在中央。维持微信锁竖屏时旋转横向牌桌及方向切换。原画避免统一重滤镜，文字采用设备字体，不下载大字体、大背景、视频或动效框架。

魄袭保留「你的手牌」「目标的手牌」两个带标题的横向牌区，花色、点数与牌名可读；观星/攻心保留原生移动区和确认。长材料区单独滚动，提示与确认可见。稳定 key 更新席位、手牌和选择节点，选择状态、滚动及焦点不因普通快照重建而中断。

## 默认动作节奏

时长是 v0.6.2 的实际参数，属于待真机调整的基线。正常模式不会把每个动作都压成一闪而过；动作层不接收点击，不锁住手牌、目标或确认。

| 场景           | 当前过程与时长                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 选牌与目标     | 选中状态收到后更新轮廓与抬牌；卡牌过渡约 500ms，合法性及最终提交仍由原生确认                   |
| 摸牌           | 牌背从中央移到该席位/本人手牌，移动 500ms，落位后短停，再用 350ms 淡出；实际手牌按授权快照更新 |
| 使用/响应/弃牌 | 从来源移到中央约 500ms，落位后停留约 700ms，再淡出 350ms；使用和响应支持公开虚拟牌             |
| 目标指向       | 伸展、停留、淡出约 900ms，用代码画线                                                           |
| 伤害           | 武将震动约 500ms；明确体力浮字约 1200ms。原生文字弹出另作普通提示，避免误当成扣血              |
| 技能           | 技能名进入、停留、淡出约 1500ms，代码光环约 1100ms，必要时指向目标                             |
| 回合           | 原生当前回合变化后，席位强调约 650ms、回合浮字约 1000ms；座次不移动                            |
| 弹窗           | 小幅缩放与淡入约 450ms，材料节点和确认区稳定                                                   |
| 阵亡/结算      | 阵亡状态及标记同步、浮字约 1200ms；结算立即可回房，不等待动画队列                              |
| 重连/切回前台  | 展示最新状态，建立新游标，不补播离线旧动作                                                     |

连续动作按原生编号先后开始，视觉可以重叠；不为播放完动画而延迟规则或选项。手机只排少量近期事件，超过三秒的旧动作跳过。提供「精简动画」并保存偏好，尊重系统 `prefers-reduced-motion`；精简模式缩短为约 120ms，不能成为默认正常节奏。

## 实现与隐私边界

`table-presentation.js` 在电脑规则 worker 捕获原生 `$draw/$throw/$damage/$damagepop/logSkill/$die` 和 `game.log` 发布点。使用/响应只在日志确实发布当前牌时记录，回合来自 `_status.currentPhase`；不靠 HP 或手牌差值猜过程。原方法继续执行，表现采集故障不会中断规则。

每个接收者单独构造牌面：摸牌者可看到自己的牌；旁人只得到暗牌，除非原生已经公开或授权该牌。公开使用/响应可显示当前虚拟牌；不携带原生事件、函数、storage、牌堆或实体牌 ID。经现有私有席位通道送到电脑镜像，再由 Node 清洗事件类型、席位、字段与资源地址。私人技能材料继续使用原隐私过滤；公开观战和普通日志不扩权，详见架构 ADR-021。

镜像保留最多 32 条短期表现；手机待播队列最多 12 条、瞬时效果节点最多 24 个。重连、隐藏、换局和结算清理积压；首次快照只建立游标。过大的快照优先释放短期动画，不能为动画丢掉合法选择。表现事件不是存档或完整动画回放。

## 验收与后续

资源预算维持牌桌 JS+CSS 不超过 60KiB gzip，动效模块不超过 15KiB gzip，不含大厅、图片、声音与同步状态。实际构建字节和验证结果记在 [运行验证](runtime-validation.md)，不据此推导微信首开秒数、帧率或公网延迟。

| 验收项   | 必须看到的结果                                                                             |
| -------- | ------------------------------------------------------------------------------------------ |
| 过程可读 | 能辨认使用者、目标、牌名、伤害/回复、技能和当前回合，正常动画有完整停留                    |
| 操作稳定 | 滑手牌、选择、取消与确认持续可用，动画不吞点击、重复包不重播                               |
| 复杂材料 | 魄袭双行可读、攻心原生限制、观星排序/跨区/确认正确，刷新仍可继续                           |
| 隐私     | 其他席位、公开观战、普通日志没有私人牌面、牌堆或 storage                                   |
| 恢复     | LAN/公网刷新、后台和线路切换不积压旧动画或旧声音                                           |
| 真机     | 原 Android 微信、iPhone 微信，350px 有效横屏、8 席、两局连玩；记录首个可操作时刻和动画表现 |

当前交付覆盖上述基础布局和常规动作；复杂技能专属大演出、全部自定义界面及原生每个皮肤的逐像素一致尚未实现。继续以无名杀原效果为参照，先由原手机复测节奏与可读性，再逐项补齐差异，不另起一套美术设计。
